# 港口放货台 —— 流转记录 → 实现对照

需求即册上那趟 NB07 的流转记录。本文把记录里的每条口径对到实现落点，
并写明唯一一处需要取舍的解释（见末节「一处解释」）。

## 那趟记录是怎么落的

| 册上那笔 | 系统落法 |
| --- | --- |
| NB07 ｜ 直发档 | `open("NB07", 300)`：300 件 ≤ 判据 th1=500 → 直发档，走三道，档和关数写死在凭证头 |
| 09:12 ｜ 关 1/3 ｜ 受理 ｜ 柜员甲 | `sign(...)` → 签认册有效笔，关次系统派 1 |
| 09:40 ｜ 关 2/3 ｜ 单证齐全 ｜ 单证员乙 | `sign(...)` → 有效笔，关次 2 |
| 09:41 ｜ 关 2/3 ｜ 单证齐全 ｜ 值班领导丙 （注意） | `resign(...)` → 后一笔压前一笔：09:40 那笔作废留痕，09:41 有效并指回被压的那笔 |
| 10:05 ｜ 关 3/3 ｜ 结关 ｜ 闸口丁 | `sign(...)` → 关齐即封口（头表已核发），留痕写「最后哪一道定的=第3道」 |
| 10:06 ｜ 关 4/3 ｜ 结关 ｜ 闸口丁 （注意） 多了一道 | 册上三道、系统走了四道 → 被拒笔：这趟不算数，以册上为准，痕留着 |

逐行回放在 `THeriDelRuleServiceTests#nb07Record_replay`。

## 落账结构（两本账 + 头表）

| 表 | 角色 |
| --- | --- |
| `t_heri_del_rule` | 凭证头：档、几道关（册上写死）、第几趟、退了几回；`node_no` 只是页面先亮的汇总数，不作依据 |
| `t_heri_del_sign` | 签认册：关口每一笔（有效/作废/被拒）都留着；`uk(bill_no,round_no,eff_gate)` 一道只容一笔有效（作废/被拒=NULL 不占位）；`uk(bill_no,round_no,attempt_id)` 同一笔重办不重复落 |
| `t_sys_oper_log` | 留痕册：谁落的、何时落的、退了几回、最后哪一道定的；每条痕起头带「趟=N｜」，抽验按趟对账 |

关口那一步动两边账本：签认和留痕**同一事务**落（`TransactionTemplate`），不能只落一处。

## 口径逐条对照

| 册上口径 | 实现落点 |
| --- | --- |
| 分档看数量；直发档当场放、换单档先换单、改提单档交上去核 | `open → classify` 按 `t_heri_bl_rule`（生效窗口内、优先级高者）定档；`release` 按档核前提（换单确认痕/交核确认痕），直发档当场放 |
| 分档谁定：港里的判据；判据没写到的，退回重定，系统不自己挑 | 数量超界 / 档没配关数 → 抛 `退回重定`，不落单但留一笔退回痕；系统不替人挑 |
| 几道关由这一档决定；说三道走三道，说两道走两道 | `gradeGates`（港里判据，可颁行可改）；开单时 `gate_total` 写死在凭证头上 |
| 走法：一道挨一道走；不许跨着走；不许两个人同时签 | 关次只能落「当前关数+1」，没有跨着走的入口；每单一把锁排队 |
| 同时落笔：后落的那一道算数；前一个作废，并留一笔痕 | 顺序重签 `resign`：前一笔作废留痕，新笔有效、`supersedes` 指回去 |
| 09:40 因上条作废，但作废这笔痕必须留着，不许悄悄抹掉 | 作废笔 `status=作废` 留在签认册，另有作废痕；抽验核它 |
| 10:06 册上三道、系统走了四道：这趟不算数，以册上为准 | 已封口后再签 → 被拒笔（`status=被拒`，不算数），痕留着 |
| 关次系统从上往下排，不许手填 | `sign` 没有关次参数，关次由系统派 |
| 数与次对不上，以册上为准 | 关数从签认册数出来（不信头表）；抽验核关次连号、头表与册一致性 |
| 关齐即封口；此后不许再往上加签；要加签先把整件事收口重来 | 关齐 → 已核发；再签/再压/再退全被拒留痕；`redo` 老趟封住开新趟 |
| 回退只摆还没定下来的那几段；已定的原地不动，也不跟着回来 | `rollback` 只退悬着的那一道（最新那笔有效签）；前头已定的笔一条不动 |
| 已定的那截，不许因为后来退了一回就当没发生过 | 回退只是把悬着笔作废留痕，已定笔不删不改 |
| 留痕：谁落的 / 何时落的 / 退了几回 / 最后哪一道定的，都写 | 留痕册逐笔；头表 `rollback_cnt`；封口痕写「最后哪一道定的」 |
| 抽验：随机抽一单倒着核；核得出的算数，核不出的那几笔不作数 | `spotCheck` 随机抽单；`audit` 从最后那道往回核，报告分「算数/不作数」两栏 |
| 页面上先亮出来的，不算数 | 头表汇总数只是投影；落签、抽验都以签认册为准，对不上点名「以册上为准」 |
| 关口那一步要动两边账本，签认和留痕必须同一次完成，不能只落一处 | 同一 `TransactionTemplate` 事务；留痕写失败 → 签认一起回滚（有测试坐实） |
| 两人同时抢着签要并发错开，先落的那一笔算数，后到的那一笔作废并记账 | 每单一把锁 + `baseStroke` 认出抢签：看到的册上那笔对不上 → 后到作废留痕；库上 uk 兜底 |
| 中途出错停下，重办只补没写的那几步 | `attempt_id` 幂等：同一笔重办照面不重复落；事务回滚后重交只补没落的 |
| 这一单归哪一档、以哪一遍为准，册上写死，取舍不替人定 | 档和关数开单写死；`redo` 照抄老趟写死的，不重定 |
| 往年已走齐的老单子，一条不动，照旧查得回 | 老趟已封住只读；`selectRound`/`listStrokes`/`audit` 照旧查、照旧核 |
| 往后加关口不许追着改老账 | `gate_total` 冻结在凭证头；改 `gradeGates` 只影响往后开的单 |

## 一处解释（记录里两条挨着看像打架）

口径表说「同时落笔：后落的那一道算数」，工程段又说「两人同时抢着签……
先落的那一笔算数，后到的那一笔作废」。按记录本身（09:40 作废、09:41 算数）
和末行总结「一道只容一笔，后一笔压前一笔」，落地为两种情形分开：

- **顺序压签**（后一个人看着册上那笔重签，如 09:41 值班领导丙）：
  走 `resign`，后一笔压前一笔，前一笔作废留痕 —— 后落的算数。
- **并发抢签**（两个人同时抢着签同一道，谁也没看着谁的）：
  走 `sign` 带 `baseStroke`（签的人当时看到的册上最后一笔；0=看到册上一笔都没有），
  系统串行落账，先落的那一笔算数，后到的作废并记账 —— 先落的算数。

两条都不抹痕：作废的笔和被拒的笔一样留在签认册上，抽验逐笔核。
